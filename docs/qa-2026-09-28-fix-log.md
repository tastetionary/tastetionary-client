**변경**

## #5 공유 링크에서 "한 번 더 돌리기"

**파일**: `apps/web/src/app/(main)/select-menu/result-share/components/SelectMenuResultShare.tsx`

**원인**: "한 번 더 돌리기" 버튼(`CRecommendButton`)은 선택 스토어(`useSelectFoodStore`)의 음식 종류·키워드로 추첨을 요청한다. 공유 링크로 들어온 사람은 스토어가 비어 있어 빈 조건으로 요청했고, 서버가 추첨할 메뉴가 없다고 답했다.

**변경**: 공유 페이지가 마운트될 때 URL 에서 복원한 음식 종류·키워드를 스토어에 넣는다. 공유받은 사람도 같은 조건으로 다시 돌릴 수 있다.

**확인**: 로컬에서 `?category=KOREAN,JAPANESE&keyword=SPICY&id=3&name=퀘사디아` 로 진입 후 "한 번 더 돌리기" → `id=83&name=쌈밥` 으로 정상 재추첨.

## #6 팝업(토스트) 글씨 안 보임

**파일**: `apps/web/src/styles/globals.css`

**원인**: 토스트 스타일(`.toast { .Toastify__toast { background-color: #253238 } }`)이 `@layer components` 안에 있었다. react-toastify 의 기본 CSS 는 레이어 없이 로드되는데, CSS 카스케이드에서 **언레이어드 선언은 레이어 안 선언보다 항상 우선**한다(명시도와 무관). 그래서 배경이 라이브러리 기본값(흰색)으로 남았고, 글씨는 흰색으로 강제돼 있어 보이지 않았다. (Tailwind v4 마이그레이션 때 레이어 안으로 들어가면서 생긴 회귀)

**변경**: 토스트 스타일 블록을 `@layer` 밖으로 옮기고, 셀렉터를 `.toast.Toastify__toast-container` 로 올려 라이브러리 CSS 보다 명시도가 높게 했다.

**확인**: 로컬에서 링크 복사 토스트가 `background: rgb(37, 50, 56)`, 글씨 `rgb(255, 255, 255)` 로 표시됨.

## #7 지도 스크롤이 길다

**파일**: `apps/web/src/app/(main)/register-review/restaurant/search/page.tsx`

**원인**: 지도 높이가 `calc(100vw - 64px)` 였다. 모바일 폭에서는 적당하지만 데스크톱(화면 폭 1,400px 이상)에서는 지도가 1,300px 넘게 커져 스크롤이 길어졌다.

**변경**: 높이를 200px 로 고정 (`h-200`).

**보완**: 지역 설정 화면(`sign-up/components/region-setting`, 회원가입·식당 고르기·마이페이지 지역 변경이 공유)의 지도도 500px 이라 같은 문제가 있었다.
고정 높이 대신 "화면 높이 - 헤더" 안에서 남는 공간을 지도가 채우도록 했다(flex). 긴 화면에서는 하단 "다음" 버튼 8px 위까지 늘어나 아래가 비지 않고, 짧은 화면에서는 최소 200px 을 지키고 나머지는 스크롤된다.
지도 div 는 `height: 100%` 가 flex 부모에서 0 이 되므로 `absolute inset-0` 으로 채운다. 로컬에서 755px·383px 두 높이로 확인했다.

## #9 리뷰 수정 시 기존 내용 프리필

**파일**

- `apps/web/src/app/(main)/register-review/page.tsx`
- `apps/web/src/features/reviews/api/index.ts` — 리뷰 타입에 `category?` 추가
- `apps/web/src/app/(main)/mypage/user/reviews/components/MyReviewItem.tsx` — 주석만

**원인**: 수정 화면은 `?update=<id>` 로 들어왔지만 식당 이름·주소만 스토어에 넣고, 키워드·가격대·한 줄 리뷰·재방문 의사는 채우지 않았다.

**변경**

- 수정 모드에서는 리뷰 관리 목록과 같은 쿼리키(`['my-reivews']`)로 리뷰를 찾아(보통 캐시에서 바로 나오고, 새로고침으로 들어오면 다시 받아옴) 키워드·가격대·한 줄 리뷰·재방문 의사를 미리 채운다. 서버가 `category` 를 내려주면 음식 종류도 채운다.
- 수정 성공 시 목록 쿼리를 무효화해 수정 전 내용이 남지 않게 하고, 선택 스토어를 비워 다음 작성에 섞이지 않게 했다.

**남은 것**: 목록 API 응답에 `category` 가 없으면 음식 종류는 다시 골라야 한다. BE 가 목록에 `category` 를 포함해 주면 자동으로 채워진다.
